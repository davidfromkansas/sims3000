# Recorded abandonment causes

An abandoned building now retains the conditions that triggered its loss of occupants. The inspection panel separates this recorded cause from current recovery guidance, so restoring electricity does not erase the explanation. Service-driven loss records the blockers at the final decline check; demand-driven abandonment and toxic-cloud evacuation have explicit causes. Multi-tile lifecycle changes synchronize the record. Reoccupation and destruction clear it.

This addresses the manual’s Query Tool instruction (p.39) to explain abandoned buildings. It records the modeled simulator’s trigger, not a reconstruction of undisclosed original formulas or every condition across the preceding months.

Save schema 124 persists a bounded, validated cause value. Version 123 and older saves migrate to unknown history instead of inventing a cause. The panel says when the original cause was not recorded.

Validation extends real abandonment, repairs, eventual growth, toxic-cloud evacuation and save/load tests. Recorded power/transport failures survive service restoration, reoccupation clears history, toxic-cloud evacuation records its source, and malformed/duplicate/unordered cause fields are rejected. Existing growth report tests exercise the recovery panel helper. No new browser abandonment playthrough was performed for this follow-up.

Feedback: inspect a newly abandoned building before and after repairing its services; compare Recorded cause with the current recovery guidance. Older abandoned buildings have no retroactive cause record.
